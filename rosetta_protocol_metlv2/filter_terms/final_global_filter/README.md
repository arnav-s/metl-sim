## Background and Provenance

This work consolidates two scoring protocols that were developed and validated independently in earlier sessions:

**Global filters** originated from `../filter_terms/final_global_filter/`, where the protocol was iteratively built to compute 23 whole-structure metrics (atomic contacts, average degree, residue counts, SASA, buried surface area, exposed hydrophobics, packing, unsatisfied H-bonds, and secondary structure composition checks). The standalone output is `filter.sc`.

**Per-residue simple metrics** originated from `../per_residue_filter_terms/per_residue_final/`, which computes 7 per-residue distributions (SASA, sidechain neighbor count, H-bonds, clashes, SAP score, and two hydrophobicity energy variants). The standalone output is `filter_per_residue.sc`.

Both protocols use two custom Talaris2013-derived weight files that zero out all energy terms except the `ref` weights, effectively isolating per-amino-acid hydrophobic reference energies. Version 1 (`total_hydrophobic_weights_version1.wts`) uses the original Talaris2013 reference weights, while version 2 (`total_hydrophobic_weights_version2.wts`) uses a rescaled set that more heavily penalizes larger hydrophobic residues (AFILMVWY).

## Combined XML Protocol: `filter_3rd_and_per_residue_metrics.xml`

The combined protocol merges the two XMLs into a single RosettaScripts file with the following sections:

**RESIDUE_SELECTORS** define four layer-based selectors — `buried_core_boundary` (core + boundary residues), `buried_core` (core only), and their complements — using SASA-based layer definitions with `use_sidechain_neighbors="false"`.

**TASKOPERATIONS** create `PreventRepackingRLT` operations that restrict filter calculations to the buried subsets by preventing repacking of surface/non-core residues.

**SCOREFXNS** registers the two custom hydrophobic weight files as named score functions (`TotalHydrophobic1`, `TotalHydrophobic2`).

**FILTERS** (global terms, 23 filters total): `AtomicContactCount` at 4.5 Å for all, core+boundary, and core-only residues; `AverageDegree` with threshold 9.4 for three scopes; `ResidueCount` for all/core/core+boundary/hydrophobic-core/hydrophobic-core+boundary; `TotalSasa` and `BuriedSurfaceArea` (total and nonpolar); exposed SASA split by hydrophobic/polar/total plus `ExposedHydrophobics` with 20 Å² cutoff; `ScoreType` for both hydrophobic score functions; `PackStat`; `BuriedUnsatHbonds`; and three `SecondaryStructureHasResidue` checks requiring VILMFYW residues in each helix/sheet element.

Note: `SSPrediction` (ss_mis) is commented out in the XML and was excluded from the protocol.

**SIMPLE_METRICS** (per-residue terms, 7 metrics): `PerResidueSasaMetric`, `SidechainNeighborCountMetric`, `HbondMetric`, `PerResidueClashMetric`, `PerResidueSapScoreMetric`, and two `PerResidueEnergyMetric` instances using the two hydrophobic score functions with custom types `hydro1` and `hydro2`.

**PROTOCOLS** section executes all 23 filters followed by the `RunSimpleMetrics` mover that computes all 7 per-residue distributions in a single pass.

## Execution

Rosetta was run via Docker using the `arnvsharma/metl-sim:latest` image.

**Step 1 — Pull the Docker image:**
```
docker pull arnvsharma/metl-sim:latest
```

**Step 2 — Launch the container with the working directory mounted:**
```

```

Note: the container drops you into `/workdir` by default. You need to `cd` up a level and into `/rosetta` to reach the mounted protocol files. This is a minor annoyance with the container setup worth remembering.

**Step 3 — Run the protocol:**
```
time rosetta_scripts @flags_filter_temp > flags_filter_temp.log 2>&1
```

The flags file (`flags_filter_temp`) specifies:
```
-s flags_relax_v6_no_cartstructure_0001.pdb
-parser:protocol filter_3rd_and_per_residue_metrics.xml
-out:prefix filter_3rd_per_residue_
-jd2:failed_job_exception false
-out:file:score_only filter_3rd_per_residue.sc
-out:level 100
-run:preserve_header true
```

The run completed in under 5 seconds total, with most of that time consumed by Rosetta's startup/initialization rather than actual scoring.

## Validation

The output score file (`filter_3rd_per_residue.sc`) was compared against the two standalone outputs using a Python notebook (`analyze_outputs.ipynb`). The validation had two parts:

**Column check:** The set of columns in the combined output (excluding `total_score` and `description`) was compared against the union of columns from `df_global` and `df_per_residue`. All columns matched — nothing missing, nothing extra, and no unexpected overlap between the global and per-residue column sets.

**Value check:** Every numeric column was compared element-wise using `np.isclose` with `atol=1e-5`. All global filter values matched exactly. All per-residue metric values matched exactly. The only column with any discrepancy was `pack` (PackStat), which differed by approximately 1e-2 (order of magnitude larger than the tolerance, but trivially small in absolute terms and consistent with known floating-point nondeterminism in PackStat's cavity-ball algorithm).

The `total_score` column is produced by both sub-protocols with different values (it reflects whatever Rosetta's default score function computes, which is not relevant here) and must be dropped during post-processing regardless of which run is used.

The `description` column differs across the three files because each run stamps its own output prefix into the tag (`filter_`, `filter_per_residue_`, `filter_3rd_per_residue_`), which is expected and not a data concern.

## Conclusion

The combined XML protocol (`filter_3rd_and_per_residue_metrics.xml`) successfully reproduces all global filter values and per-residue metric values from the two standalone protocols. The only deviation is the `pack` filter at ~1e-2, which is within the expected stochastic range for PackStat and is not a concern. This combined protocol can now be used as a single-pass scoring step, eliminating the need to run two separate Rosetta jobs and merge their outputs.
